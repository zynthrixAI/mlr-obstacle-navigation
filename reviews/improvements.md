# Review: PPO safety shield (T5) and causal temporal tracking (T2c)

**Verdict: CHANGES** — both analyses are methodologically sound and the CSV numbers check out; the must-fixes are about the report, which currently cannot even be rebuilt with the new tables.

## 1. Safety shield (`rl/evaluate.py: shield`, agent `ppo_shield`)

- **Geometry — PASS.** `lidar()` casts at `th + 2*pi*i/36` (index 0 forward, CCW), `_ANG = i*10 deg` matches; `fwd = r cos, lat = |r sin|`. Exact check: a forward step collides iff some surface point is < 0.15 m from the next centre (0.1, 0). Because clearance at the current pose is always >= 0.15 (start sampled at >= 0.4, turns do not move, forward is refused on collision), every such point satisfies fwd > 0.05, lat < 0.15, fwd < 0.25, so `fwd > 0`, `lat < 0.20`, `fwd < 0.35` is a strict superset with 5 cm / 10 cm margins against the 1 cm + 1 % range noise. Veto direction reuses `sectors36` (checked in `reviews/methodology.md`). `inf -> 1e6` change (6255c2c) gives identical decisions (avoids NaN from `inf*sin(0)`).
- **On-board only — PASS.** `e.last_rays` is the very array `_obs` builds the agent observation from (same noise, same dropout); nothing from `world`. NaN = free is a design choice; it did not cause any of the 5 collisions (dropped rays were at 170 deg, 140/340, 30, 90/270).
- **Same held-out protocol — PASS.** Same `run_policy`, `RL_EVAL`, deterministic `start_goal_for`, noise RNG re-seeded `1000+seed` per run; 150 maps x 3 PPO seeds.
- **Existing rows unchanged — PASS.** `grep -v ppo_shield results/T5_rl.csv` is byte-identical to `git show 33b78a4~2:results/T5_rl.csv`; the six pre-specified AC8 rows in `T5_acceptance.csv` are identical; shield rows are prefixed `[post-hoc]` and appended.
- **Fairness.** Acceptable *if labelled*: the rule was written after inspecting PPO's held-out collisions, but its two constants are derived from robot geometry (0.15+0.05, 0.15+0.10+0.10), unchanged since 9928aef, no retraining, and the narrow failure (0.033 vs reactive 0.020) is reported as a fail. It is nonetheless a second use of a set documented as "used once" — the report must say so.
- **Why narrow still has 3.3 % (5/150) — diagnosed, not a shield bug.** Collisions: map 200011 (all 3 seeds, step 8-9; reactive and plain PPO collide there identically), 200062 (seed 0), 200002 (seed 1). Replaying the fatal step: true clearance 0.15-0.21 m, next-pose clearance 0.05-0.12 m, yet **no ray in the front half-plane returned < 0.47 m** (true 36-ray min 0.48-0.85 m). The nearest primitive is in every case a **zero-thickness corridor wall approached end-on** (`t = 0.00/1.00`, i.e. the wall tip at the 1 m doorway, e.g. endpoints in robot frame A=(0.152, -0.014), B=(7.152, -0.057)). Edge-on, the segment subtends 0.6-7.6 deg (a 0.1 deg sweep shows 6-76 of 1801 sub-rays < 0.35 m), below the 10 deg ray spacing; the generator's 360-ray scan sees it at 0.16 m. So the 36-ray LiDAR is blind to doorway edges in narrow maps; no LiDAR-only shield can veto what it cannot see. This is a simulator artefact (walls have no thickness) and should be stated as a limitation of the "0 % collisions" claim.

## 2. Temporal tracking (`tasks/temporal.py`, T2c, F10)

- **No label leakage — PASS.** `link_tracks` uses only `bearing_*`, `pose_*`, `f_mean_r`; one-to-one greedy nearest centroid <= 0.3 m to the scan at `step - SEG_EVERY` of the same `episode_id` (asserted). History = self + `prev` chain (<= 5), `track_len` filled in step order; `t_view_spread` relative to the current view. All causal; computing on the full file before subsampling is therefore fine (history rows lie in the same map, hence the same fold).
- **Subsample / folds / pipeline / bootstrap — PASS.** Same `.sample(n=60000, random_state=0)` on the same file, index and feature equality asserted; `outer_folds(g)` on the same groups; RF-engineered reproduces T2 to all digits (0.6353670951826257), which also proves fold identity. Imputer+scaler in `make_pipe`, inner `GridSearchCV(GroupKFold(3))`; CI via `per_map_stats`/`bootstrap_maps` over maps.
- **"All linked pairs share the same label" — expected, not a proxy.** Verified: 58.1 % of segments link, 0 of 123 k links disagree. Cause: the generator enforces >= 0.45 m (open/cluttered) or 0.6 m (narrow) spacing between object surfaces, so two different objects' centroids are never within 0.3 m; links cannot cross objects. Predecessors are **not duplicates**: the robot moves 0.24 m and turns 20 deg between scans; median relative change 30-40 % in `f_n`, `f_chord`, `f_lin_rms`, 4 % in `f_mean_r`; 0 % of links have all features within 1 %. No label-derived quantity (label, purity) enters any `t_*` feature. One geometric side-channel exists: link success itself is class-dependent (54 % of walls have `track_len` 1 vs 20-26 % of obstacles/targets, because a wall's visible-part centroid moves with the robot). Ablation with a fixed RF on the same folds: eng 0.635; + `track_len,t_hist_n` only 0.661; + all other `t_*` (no track_len) 0.712; all 0.713. So ~0.08 of the gain comes from multi-view aggregates (`t_max_chord`, `t_mean_circ_r`, ... top importances) and ~0.03 from track persistence, which is legitimately observable on-board too.
- **Numbers — PASS.** `T2c_acceptance` values equal `T2c_temporal`/`T2c_by_track_len` arithmetic exactly; bucket n sum to 60 000; F10 bars match `T2c_by_track_len.csv`; commit message (0.713 vs 0.635, +0.078, CI 0.071-0.084) matches.
